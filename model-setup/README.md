# model-setup

OpenTofu for the **model + vector store** side of the self-hosted server:
**phi-4-mini** served by llama.cpp and **PostgreSQL + pgvector** — deployed as
a single **podman-compose** stack managed by OpenTofu. There is no Qdrant, no
MCP server and no MQTT anymore: agents connect to the model directly and store
results in Postgres.

## What it runs

The stack renders as `/var/spool/aigents/compose/compose.yaml` (project
`aigents`) and is applied by the `start_compose` step during `tofu apply`:

| Service      | Container | Host port      | Notes                                                          |
|--------------|-----------|----------------|----------------------------------------------------------------|
| PostgreSQL + pgvector | `aigents-postgres` | `15432` | schema seeded once on empty data dir (vector dim **3072**) |
| phi-4-mini crews | `aigents-phi4` | `18080` | OpenAI-compatible `/v1`, model alias `phi-4-mini`, 2 parallel slots |
| phi-4-mini CLI | `aigents-phi4-cli` | `18081` | second instance, CLI/Odysseus only, 1 slot, shared mmap weights |
| model-fetch  | (one-shot) | —              | downloads the GGUF weights; profile `fetch`, run once via `podman-compose run --rm` |

Both model instances run the CUDA llama.cpp image
(`ghcr.io/ggml-org/llama.cpp:server-cuda`) and share the GPU via the CDI device
`nvidia.com/gpu=all`, which requires the **nvidia-container-toolkit** on the
host (`nvidia-ctk cdi generate` output under `/etc/cdi` or `/var/run/cdi`).

## Usage

```sh
tofu init
tofu plan
tofu apply
```

`tofu apply` in order:

1. writes `~/.config/containers/storage.conf` (image graph on the aigents
   volume), directories, credentials
2. renders the compose file + the initdb schema
3. runs `podman-compose -p aigents --profile fetch run --rm model-fetch`
   (downloads `Phi-4-mini-instruct-Q4_K_M.gguf`, ~2.5 GB, idempotent)
4. `podman-compose -p aigents up -d`, then waits for the model health endpoint

### Verify

```sh
curl http://127.0.0.1:18080/health          # crew instance
curl http://127.0.0.1:18081/health          # CLI/Odysseus instance
curl http://127.0.0.1:18080/v1/models        # -> "phi-4-mini"
podman-compose -f /var/spool/aigents/compose/compose.yaml -p aigents ps
```

### Start / Stop

The desired stack state is controlled by the `service_state` variable. Stop the
model + database (volumes and GGUF weights are kept) or bring them back up:

```sh
tofu apply -var service_state=stopped   # stop postgres + phi-4-mini
tofu apply -var service_state=running    # start them again (default)
```

## Configuration knobs (highlights)

`model-setup/variables.tf` is the source of truth:

- `model_repo` = `unsloth/Phi-4-mini-instruct-GGUF`,
  `model_file` = `Phi-4-mini-instruct-Q4_K_M.gguf`,
  `model_alias` = `phi-4-mini`
- `embedding_dimensions` = **3072** — must match the model's hidden size
  **before the first DB boot** (the initdb hook only runs on an empty data
  dir; change it only before initialising the cluster)
- `model_context_size` / `model_kv_cache_type`
  — context `16384`, KV cache `q8_0`; `model_threads` defaults to 0 = all cores
- `model_gpu_layers` = **99** — every layer is offloaded to the RTX 3060
  (CUDA image + CDI `nvidia.com/gpu=all`); set `0` for a pure-CPU run
- `model_cli_port` (default `18081`) / `model_cli_parallel_slots` (default `1`)
  — the second, CLI/Odysseus-dedicated instance; the crew instance uses
  `model_port` (`18080`) with `model_parallel_slots` (`2`)
- `bind_address` defaults to `127.0.0.1`; set `model_api_key` before
  switching to `0.0.0.0`
- `postgres_password` is generated by OpenTofu when left empty and stored in
  `/var/spool/aigents/database/secrets/credentials.env` (mode 0600) together
  with `POSTGRES_DSN`, `MODEL_URL`, `MODEL_NAME`. The agent quadlets mount this
  file read-only.

## State layout

```
/var/spool/aigents/
├── containers/storage/        podman image + layer graph
├── compose/compose.yaml       the rendered stack (mode 0600)
├── model/                     GGUF weights
└── database/
    ├── postgres/              PostgreSQL cluster (pgdata)
    └── secrets/credentials.env  credentials for agents + tools
```

## Troubleshooting

- The stack is just a compose file: fix the cause and re-run
  `podman-compose -f /var/spool/aigents/compose/compose.yaml -p aigents up -d`,
  or `tofu apply` to re-apply.
- First apply is slow: it pulls images, downloads ~2.5 GB of weights and mmaps
  them before `/health` responds.
- If your host's `network-online.target` never activates, keep
  `skip_network_online_wait = true` (default) so quadlets don't stall.
